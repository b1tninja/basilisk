§35c/§35d — the keypair, which today renders as two JWK blobs and nothing else

Two artifacts, two good tiles. Emission is unchanged in content and count; what changed is that both halves now carry role: "key" and a public/private tag, so the registry can find them. Merging them into one tile was rejected — it would put a private JWK back on the artifact record, which the engine deliberately withholds.

The mask rule, visible in one row. Copy is disabled (its output derives from the masked material and lands on a clipboard the mask does not govern). §34c — the outward confirmation, in §27's banner grammar

Same shell as ApprovalBanner: border-l-2 in --warn, warn-tinted background, a <dl> of facts, ghost cancel and secondary confirm, inline at the object it concerns. Absent by design: the session-grant checkbox, the per-run batch, and the request counter — there is no defensible "don't ask again" for an irreversible outward act.

§32f — no match, rendered honestly

An artifact whose role no kind claims gets exactly today's raw-text path and the role verbatim on the badge. No warning, no scare word: the value is fine, only our description of it is missing. The gap is surfaced by artifact-kinds.test.js, not by a toast to a user who did nothing wrong.
