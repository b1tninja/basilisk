Artifact tiles — visual mock

Companion to VISUAL-DESIGN.md (§39–§46), which carries the reasoning. This file carries the pixels. Every tile appears in both colour schemes side by side; the tokens are copied verbatim from web/src/css/site.css and scoped to [data-theme] so both render at once. Sizes marked PIN in the stylesheet are the §33a values confirmed by getComputedStyle against the shipped OutputList.

§41 — the action row: three tiers, three weights, one hue

The hard case first, because it is the one that decides the vocabulary: a tile carrying four inert actions, one local, and one outward. If tiers were hues this row would be a rainbow; if they were all one weight it would be a toolbar. Weight is carried by fill and label darkness; the single hue is spent on the one action that leaves the machine.

Rejected: --caret for the local tier (the previous mock's choice). Blue is the caret colour and carries "this is where the insertion point is" everywhere else in the toolkit; spending it here both dilutes that and puts three hues inside a 22px row. Rejected too: brand fill on Publish, which is what ships today — brand is this codebase's "do this", and the one action that cannot be undone should not be the one the eye lands on.

The private tile's publicView renders while masked: algorithm, fingerprint and public line derive only from the public half, so showing them is not a mask bypass — the rule is "a masked tile may render only what does not derive from the masked material" (§33e).

§46 — 375px, where the action row breaks

The tile is fluid; the action row is the only part that has to give. It wraps rather than scrolls, the group separators survive the wrap, and the outward action stays last in DOM order — so it stays last in tab order and ends up alone on the final line, which is the correct emphasis by accident of the ordering rule rather than by a special case.
