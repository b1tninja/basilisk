# Agent + SSH — implementation status

Checklist for building [AGENT-SSH-DESIGN.md](./AGENT-SSH-DESIGN.md), in
dependency order: pure encodings first (testable against `ssh-keygen` with
no UI), then vault multi-kind, then the boundary ops + approval UI, then
the CLI socket agent. Every unit lists acceptance criteria measurable by
test or by browser measurement (`getComputedStyle`/DOM, per HANDOFF —
screenshots are unreliable here). **Everything below is not started.**

Engine capabilities this design needs that do not exist today are called
out inline as ⚙ — do not discover them mid-implementation.

## 1. SSH encodings (pure JS, no UI) — §29

- [ ] **`lib/ssh/wire.js`** — RFC 4253 public blob encode/decode
  (string/mpint/uint32 fields) for ssh-ed25519, ecdsa-sha2-nistp256/384/521,
  rsa-sha2. Accept: round-trips fixtures generated by `ssh-keygen` for all
  five algorithms, byte-exact both directions; malformed blobs fail with a
  named field, not an offset.
- [ ] **`lib/ssh/openssh-key-v1.js`** — unencrypted private container
  encode/decode (`cipher=none`, `kdf=none`). Accept: decodes an
  `ssh-keygen -t ed25519 -N ""` file to a working key; encodes one that
  `ssh-keygen -lf` fingerprints identically; a bcrypt-encrypted file is
  refused with the §29f message verbatim (string-asserted, the
  `share-check.js` precedent).
- [ ] **`lib/ssh/fingerprint.js`** — SHA-256 over the public blob,
  `SHA256:` + unpadded base64. Accept: equals `ssh-keygen -lf` output for
  every fixture.
- [ ] **`lib/ssh/sshsig.js`** — sshsig encode/decode/sign/verify
  (namespace, hash sha512|sha256, armor). Accept: verifies a checked-in
  `ssh-keygen -Y sign` fixture; ed25519 sign output is byte-identical to
  `ssh-keygen`'s for the same key/payload/namespace (deterministic per
  RFC 8032); namespace mismatch fails with the §31c message; tampered
  payload fails.
- [ ] **Fixtures** — `ssh-keygen`-generated keys, public lines,
  fingerprints, and sshsig blocks checked in under `src/test/fixtures/ssh/`
  with a README noting the generating commands. Accept: fixtures load in
  Vitest with no network and no local `ssh-keygen`.

## 3. Vault multi-kind — §28

- [ ] Record `kind` field (absent = pgp), `publicLine` for ssh kind;
  schema bump in `vault.js`. Accept: legacy records list as pgp untouched;
  a saved ssh key round-trips kind + publicLine.
- [ ] ⚙ Kind-aware id handling — `normalizeVaultFingerprint` strips
  non-hex today and would destroy `SHA256:` base64 ids; every caller
  (vault, vault-unlock, vault-session, agent-ops, recipient matching)
  audited. Accept: unit tests for both id shapes; PKESK matching
  (`vaultKeyMatchesRecipients`) unaffected for pgp keys.
- [ ] `agent.save` accepts `keypair` input → kind ssh (mappable alg) or
  raw; stores openssh-key-v1 / PKCS#8 payloads. Accept:
  `genkey ed25519 | agent.save` lists as ssh with a correct fingerprint;
  `genkey x25519 | agent.save` lists as raw; passphrase protection for
  non-pgp kinds is refused with the §28b message (not silently downgraded).
- [ ] `agent.unlock` on non-pgp kinds emits `keypair`. Accept:
  `agent.unlock SHA256:… | ssh.encode` runs; §26c exposure treatment
  applies (tile masked).
- [ ] `agent.list` gains `kind` (+ `publicLine` for ssh). Accept: JSON
  asserted; CLI output unchanged in shape otherwise.
- [ ] Listing UI — My Keys page (`my-keys-mount.js`) and Keyring tray:
  kind badges via `data-key-kind` + enumerated CSS, kind-formatted ids,
  ⧉ public-line copy on ssh rows, disabled passphrase radio with honest
  copy. Accept: measured in catalog + live page (`getComputedStyle` on
  badge tones); copy button writes the exact public line (clipboard test
  with real input event, per HANDOFF's transient-activation note).
- [ ] `agent.list` tile renders rows (kind badge, id, protection,
  lastUsedAt) with raw JSON one toggle away. Accept: catalog section.

## 4. Boundary ops + approval — §26, §27, §31

- [ ] ⚙ **Engine pause-for-approval** — a step must be able to suspend its
  cell pending a UI decision. Reuse the `waiting-peer` pause machinery
  (design v2 §21a) rather than a new async model; the gate function is
  injected by the shell like `setClipboardReadGate`. Accept: engine test
  drives approve/deny/cancel through a stubbed gate.
- [ ] `agent.sign` / `agent.decrypt` registered per §26f;
  `recipeNeedsMainThread` covers them. Accept: verb smoke (with a stubbed
  gate + WebAuthn PRF stub, the `agent.save protection=passkey` precedent);
  sign output for a pgp key verifies via `gpg.verify`, for an ssh key via
  `ssh.verify`; `agent.decrypt` on an ssh key fails with the §31c
  wrong-kind message.
- [ ] Approval banner widget — §27b contents (step text, key identity,
  payload digest + text preview, namespace/mode), §27c actions
  (Deny / Approve once / session checkbox), §27d loop counting + per-run
  batch. Accept: catalog states for single, loop (1-of-N with batch
  offer), passkey, decrypt, and denied; measured tones (`--warn` left
  border) and button weights.
- [ ] RunBar `waiting-approval` state. Accept: catalog state; live run
  pauses at the cell and Cancel resolves as deny with the §31c cancel
  message.
- [ ] Session grants — store keyed (key id × sign|decrypt), TTL tied to
  `VAULT_SESSION_TTL_MS`, revoked by Lock / Clear sensitive / idle scrub;
  Keyring row shows `approved · N uses · countdown`. Accept: unit tests
  for scope + expiry; counter increments on a granted run (live check).
- [ ] §26c `data-key-exposed` chip treatment — underline on
  `agent.unlock` chips and every chip consuming the exposed slot
  (slot-graph walk). Accept: computed style shows the `--warn` underline
  on exactly the consumer set for a fixture recipe; no underline on
  boundary-op chips.
- [ ] ⚙ `exposure: "exports-secret"` StepSpec field + ToolCard warn chip;
  `agent.unlock` doc steer updated. Accept: ToolCard catalog state; chip
  absent on `agent.sign`'s card.
- [ ] Shelf split — `boundary` shelf (order 0) + `vault` (order 1), glyphs
  `agent-boundary` / `agent-sign` / `agent-decrypt`. Accept: drawer order
  measured; glyphs render.
- [ ] Error strings per §31c, asserted verbatim in tests (the
  `share-check.js` wording-is-the-feature precedent).
- [ ] CLI `--approve <id>[:sign|decrypt]` / `--approve-all` + per-use
  stderr audit line; refusal message + exit 3 without the flag. Accept:
  CLI tests for refuse, scoped approve, audit line format.

## 5. CLI socket agent — §30c, §27f

- [ ] `basilisk agent --ssh` — draft-miller-ssh-agent over
  `$SSH_AUTH_SOCK` / `\\.\pipe\openssh-ssh-agent`; request-identities +
  sign-request backed by loaded keys. Accept: `SSH_AUTH_SOCK=… ssh-add -l`
  lists the keys; a real `ssh`/`git` signature made through it verifies.
  (Needs a developer-run integration check on both socket flavors — CI
  can cover the protocol layer with an in-process client.)
- [ ] Per-key `confirm`: TTY prompt per signature; no TTY →
  `SSH_AGENT_FAILURE` + stderr line, agent stays up. Accept: protocol
  test with a stubbed TTY; failure response asserted.
- [ ] `basilisk agent --status` per §30b format. Accept: output asserted;
  states "not running" cleanly when the socket is absent.
- [ ] **Deliberately absent**: any browser surface claiming CLI agent
  state (§30b). Accept: nothing to build — guard is review, not code.
