35 Glyphs over tiny text — tray tabs and kind badges

The real uniformity rule already answers which system these belong to: docs/TOOLKIT-WIDGETS.md says "one glyph renderer [Glyph, op icons only]; lucide only for non-op chrome." A tray tab and an OutputList kind badge are chrome, not ops — so the fix isn't a new custom icon system, it's applying an icon library the codebase already depends on to two places that currently render text-only. 35a the six tray tabs. 35b the kind badge that appears on every single OutputList row. 35c the one place a glyph would be wrong to add.

35a Six tabs, six lucide icons — solves 34a's narrow-width squeeze too
"Connections" at 10.5px was already the tightest label in 34a's six-way split; an icon-only tab bar removes the wrapping problem entirely rather than needing ever-smaller type. Text doesn't disappear — it becomes the tooltip, so a new user still gets the word once, on hover, and everyone else stops re-reading six labels a hundred times a session.

At ≥960px, keep the word beside the icon (icon + label, not icon-only) — icon-only is the <960px collapse behavior from 32e, not the default; don't force everyone to learn six pictograms just to save the space a wide tray already has.
35b OutputList's kind badge — the highest-frequency tiny text in the app
The real OutputList.tsx row starts with a 9px uppercase kind badge — "TEXT", "KEY", "DIAG" — on every single output row in the app, which is exactly the tiny-text problem at its most repeated. A 12×12 glyph in front of the badge lets a user scan a long Outputs tab (34a) by shape before they'd even need to read the word.

35c Where a glyph would make it worse, not better
The candidate/session/channel/connState dots (25a, reused everywhere in the WebRTC toolbox) are deliberately abstract CSS shapes, not pictograms — and they should stay that way. A pictogram tempts a specific real-world object (a plug for "session," a chat bubble for "channel") that invites a wrong reading once the abstraction leaks — WebRTC's channel isn't a chat, and a plug icon on a session row implies "connected" even mid-negotiation. Shape-plus-color without representational meaning is the safer signal for exactly these four types; keep 35a/35b's icon treatment scoped to chrome (tabs, kind badges) and leave the pipeline-type dots as they are.

34 The tray, resolved — six tabs, and Keys/Slots/Params finally drawn

34a the decision: Connections stays its own tab — it doesn't fold into Outputs. Its job is live management (Close/Cancel, ongoing state, cross-notebook visibility) versus Outputs' job (at-rest artifacts, grouped by cell); those are different enough verbs that merging them would mean every Outputs row needs a management-action affordance it otherwise never has. Server preferences (STUN/TURN defaults), though, do move — they're a session-level default, the same category as the crypto profile, so they belong in Params. 34b-34d draw Keys, Slots, and Params for the first time — referenced in three turns now, never actually laid out.

33d Artifact diff — this run against the last one, not a version history
Scoped deliberately narrow: one comparison, this run vs. the immediately previous run of the same cell, not a full history browser. Most useful case is exactly the one the brief names — did changing an upstream param actually change this output, or did I just re-run and get the same bytes back?

32b openpgp-key body — packet structure, not a JWK grid
The brief calls this "the richest and least designed" — correct, it's the one snapshot shape InspectorArtifact.tsx doesn't branch on at all. An OpenPGP transferable key (RFC 9580) is a tree — primary key, subkeys each with their own binding signature, user IDs each with a self-signature — not a flat field grid like a WebCrypto keypair. The tree needs its own body, reusing Rows for leaf fields but adding one level of nesting the current component has no concept of.

32c Finishing value display: reveal timeout, expand for every artifact
Three small, real gaps against an otherwise-complete widget. First, name the already-correct behavior as a decision so nobody "fixes" it: format bar and inspector body are mutually exclusive per row, never both. Second, a revealed secret has no auto-hide — the brief explicitly asked whether reveal times out; it should, since a masked value with no timeout is a screen-share leak waiting to happen. Third, Expand only appears for network types — a keypair or a 4 KB hexdump body can't open in the Sheet, so the "preview / inline / window" three-tier idea is only real for one type family.

32e The tray as one surface — Keys · Slots · Outputs · Inputs · Params
The single biggest real gap. Today it's two unrelated Sheets (Keyring, Variables); the design calls for one persistent tray with five tabs. Outputs is genuinely new — every cell's OutputList in one place, grouped by cell, so "what did this notebook produce" doesn't mean scrolling the whole pipeline. Inputs holds runtime secrets that never touch the recipe text (pasted messages, share mnemonics) — this is where turn 21a/22a's "runtime secrets move out of cells" decision actually has to live.
