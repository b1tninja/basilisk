21a Quorum as a toolbox — the run boundary is the session boundary
Decision: quorum.offer / join / send / recv / close sit in the shelf's category tree like any other kit, wrapping QuorumSession 1:1 — no separate Quorum page. The design problem the old page didn't have: offer and join aren't instant. Running a notebook that contains one now has a real waiting state, not just idle/blocked/running (19g) — so the run pauses at that cell until a peer connects, the same way it already pauses at a blocked cell, just for a different reason.

New SessionStrip component (cell-level, same slot pattern as 19h's READINESS row): state: 'offering'|'waiting'|'connected'|'closed'. quorum.offer's output is two things — an inviteBlob (PGP-signed, goes through the existing Copy/Publish affordance from 20h) and a live sessionHandle that send/recv/close downstream read as their input. rtc.ice is a config source op (params: STUN/TURN list) upstream of offer/join; stun.check is a one-shot diagnostic whose output is a plain OutputList row (20h), not publishable. WebRTC's main-thread requirement means offer/join can't run inside whatever isolation agent.* steps use — they need to be flagged main-thread-only in the op registry the same way, if agent.* already has such a flag.
