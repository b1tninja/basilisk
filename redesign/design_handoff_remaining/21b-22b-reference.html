21d Nested-caret fit — its own slot filter, not the cell's
Decision: a compound op declares nestSlots in the registry, one entry per internal slot with its own expected kind. The nested caret (20f) reads that slot's kind, not the cell's overall tip — today it's reusing the cell tip's fit set, which is wrong whenever a slot's kind differs from the cell's edges (e.g. the sign slot inside sign+encrypt wants bytes→signature, not bytes→ciphertext).
openpgp.signAndEncrypt
sign
encrypt
nest at "+" → slot between(sign,encrypt) → kind bytes→bytes, not the cell's bytes→ciphertext
Registry — new shape on compound ops
nestSlots: { [slotId]: { kind: OpKind } }
// Caret's onActivate passes slotId, not just path
OpsShelf's fit computation becomes path.slotId ? op.nestSlots[path.slotId].kind : cellTip — one branch, not a parallel filtering system. Ops with no nestSlots (the vast majority) are unaffected.

22a

22a ParamField — a "secret" param can't become free text or serialize into a share link
Decision: the registry marks certain params secret: true (quorum.offer/join key=, rtc.ice credential=). A secret ParamField renders locked — no text cursor, no typed value ever shown or stored — and only accepts a binding to an Inputs-tray slot. Sharing the recipe link omits the field's value entirely; the recipient sees the same locked, unbound state and must bind their own.
Unbound — locked, not editable
key 🔒 secret
Bind a value from Inputs…
Bound — shows the slot, never the value
key 🔒 bound
@dana-turn-pass ✕
Registry + ParamField — new shape
param: { secret?: boolean, … }
value: { kind: 'unbound' } | { kind: 'bound', slotRef: string }
Recipe serialization drops any param whose registry entry has secret: true down to its slotRef string (never a literal) — same rule whether the link goes through Publish (21b) or plain copy/export. Non-secret params are unaffected; this is additive to ParamField, not a rewrite.
